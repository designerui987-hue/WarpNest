# WarpNest v3 review — 13 November 2026

## Scope

Reviewed the Swift package, core services, SwiftUI flows, tests, and supplied project documentation. Extracted source into the current workspace; the original ZIP is unchanged. Included documentation was treated as project context and claims to verify, not as additional user instructions. No interactive UI walkthrough was performed.

## Findings

1. **P1 — Restore link validation bypass (fixed).** The validator skipped package descendants and exempted every link with `/dosdevices/` anywhere in its path. Four direct filesystem regression cases demonstrated acceptance of external links under a nested `dosdevices`, a non-drive name, a nested drive mapping, and a `.app` package. Restore now inspects package contents, propagates inspection errors, and restricts external-link exceptions to direct drive-letter mappings under the prefix's root `dosdevices`. Internal links and standard Wine mappings remain permitted. On this host, system unzip rejected the initial absolute-link ZIP fixtures before application validation; the regression demonstrates the application validator defect, not an end-to-end extraction exploit on this host.
   - Code: `Sources/WarpNestCore/Bottles/BottleService.swift`, `validateRestoredSymbolicLinks(in:)`.
   - Tests: `testHiddenEscapingLinks`, `testStandardWineDriveLinks`.

2. **P1 — Re-importing a runtime breaks existing bottles after restart (open).** `AppViewModel.importRuntime` constructs a new adapter ID, deletes the existing registry entry for that root, and persists the replacement. Existing bottles retain the original runtime ID. The old adapter remains in memory until restart, masking the failure. Preserve the existing ID when importing the same canonical root, and propagate registry write failures.
   - Code: `Sources/WarpNest/ViewModels/AppViewModel.swift:135`.

3. **P1 — Process completion can wait indefinitely on child-owned output pipes (open).** `ProcessSupervisor.handleTermination` synchronously reads both pipes to EOF after the direct process exits. A surviving descendant holding either write end open can block this actor, preventing completion and supervisor termination requests. Use bounded asynchronous draining and test a parent that exits while its child retains stdout/stderr. This finding is from source inspection; no dedicated reproduction was run.
   - Code: `Sources/WarpNestCore/Supervisor/ProcessSupervisor.swift:226`.

4. **P2 — Failed runtime verification is not enforced consistently (open).** Startup registers failed validation results as unverified adapters, but Settings labels every non-simulated adapter “Verified,” and `LibraryService.launchGame` checks only adapter presence. Existing bottles can therefore launch through an adapter that failed validation. Gate launch and presentation on `isVerified`.
   - Code: `Sources/WarpNest/Views/SettingsView.swift:28`, `Sources/WarpNestCore/Library/LibraryService.swift:208`.

5. **P2 — Archive timeout is unused (open).** `executeSubprocess` accepts `timeoutSeconds` but never applies it. A stalled zip/unzip process can leave backup/restore waiting indefinitely and retain the backup lock. Add deadline-driven termination and cleanup.
   - Code: `Sources/WarpNestCore/Bottles/BottleService.swift:208`.

## Product gaps

Core backup/restore and shortcut removal exist but are not exposed in the current UI. Bottle deletion immediately removes data without a confirmation step. The planned game details/configuration editor is not present. These should be scheduled after correctness fixes.

## Validation

The original suite passed all 23 tests, including the four real Wine tests using the runtime already present at the tests' hardcoded path. The four new malicious-link cases failed against the original validator, while the legitimate-link case passed. After the fix, all 7 archive tests passed (including four parameterized malicious-link cases and the legitimate-link case). The full-suite rerun during development passed the other 24 tests, including real Wine, and caught a canonical-path comparison issue in the new legitimate-link test; that issue was corrected and the entire archive suite then passed. The final source also rebuilt successfully. No final full-suite rerun was needed after that localized correction.

## Recommended next task

Preserve runtime identity across re-import and test cold-start bottle relaunch. The remaining review items above are not fixed by this archive-validation change.
